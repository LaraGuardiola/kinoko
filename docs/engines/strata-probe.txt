## What the five answers mean for Kinoko
1. `delta.reasoning_content` carries thinking; it never arrives inside `content` (0 occurrences in a
   full reasoning answer) and `<think>` tags are not used. The `<think>` splitter stays in the code
   for other engines, but it is disarmed until a tag is actually seen.
   `reasoning_effort` is honored: `"off"` sent 0 reasoning frames and `"low"` sent 34 for the same
   question, so the config knob works end to end.
2. Tool calls stream in fragments (5 for one call) whose arguments concatenate into valid JSON, so the
   existing accumulate-then-parse approach is right.
3. Aborting really frees the engine: after cutting a generation at 1.5s the next request's first delta
   arrived in 1.1s. So NO startup warning, NO capped maxOutputTokens and NO abort workaround is needed
   (see docs/engines/strata.md).
4. The prompt prefix IS reused: a ~6,000-token prefix read cold took 13.1s, the same prefix plus one
   extra message took 0.42s (31x faster). History therefore has to stay byte-stable and append-only
   (see docs/phases/05-session-context-compaction.md).
5. A `usage` chunk is sent with `prompt_tokens_details.cached_tokens` (0 here, the prefix was not a
   repeat). Usage and cacheRead are both mapped.
